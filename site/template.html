Whose turn
is it? Yours.

いま、誰の番？
あなたです。

junban is a tmux plugin that badges each tab when an AI coding agent (Claude Code, Codex, Gemini) is waiting on you, and shows the one key to press. No more finding out an agent sat for twenty minutes waiting for you to approve a psql command.

junban は tmux のプラグインです。AI エージェント（Claude Code・Codex CLI・Gemini CLI）が返事を待っているとタブに印を付け、次に押すキーをステータスバーに出します。エージェントが psql の実行許可を20分も待っていた、ということがなくなります。

curl -fsSL https://raw.githubusercontent.com/Nameless-LLC/junban/main/install.sh | bash

Installs into tmux and connects Claude Code if you have it · MIT · tmux ≥ 3.2, bash, git

junban を tmux に入れ、Claude Code があれば連携も設定します · MIT · tmux 3.2 以上、bash、git が必要

The problemこんなこと、ありませんか

Every tab looks the same. One of them is waiting on you.

どれが返事を待っているのか、見ても分からない。

Plain tmux導入前

work1 billing2 fix-ci3 pricing4 db5 k8s6 docs

You find out by opening each one.

どれが待っているかは、1つずつ開かないと分かりません。

With junban導入後

work1 ● billing2 ✋ fix CI3 ✓ pricing4 ✋ db migration5 ● k8s6 docs

The badges say who is waiting. Alt+a goes to whoever needs you first.

各タブに状態の印が付きます。Alt+a で、いちばん先に返事が要るものへ移動します。

使い方は画面に出ます。

ステータスバーのいちばん下に、よく使うキーを表示します。返事待ちがあればその上の行に「Alt+a で移動」が、未確認の完了があれば「Alt+a で確認」が出ます。

Why this one特長

The more agents, the more it pays off.

エージェントが多いほど便利です。

Badges don't get stuck

「作業中」のまま残らない

Press Esc mid-task and the badge still updates. Hooks alone miss that; junban also checks Claude Code's own session records.

Esc で止めても、Claude Code の記録（~/.claude/sessions）を見て表示を直します。

Most urgent goes first

返事待ちを先に、長く待たせた順に移動

Alt+a takes you to the agent that needs you: questions and approvals before finished work, longest wait first.

Alt+a で、返事待ちのうちいちばん長く待っているエージェントへ移動します。返事待ちがなければ、完了したものへ移動します。

One line on what it needs

何を求めているかを1行で

Each agent's question, or how its work turned out, in one line. Finished work also shows what changed: files, commits, PR. If you set up notifications (ntfy, notify-send), they carry the same line.

何を聞いているか、何が終わったかを、ステータスバーと Alt+f の一覧に1行で表示します。終わったものには、変更したファイル数・コミット数・PR も出ます。通知（ntfy・notify-send）を設定すると、同じ1行が届きます。

Idle windows step aside

放置したウィンドウは下へ

Windows untouched for a day get a dim z and drop to the bottom of the Alt+f list, so the one that needs you isn't buried.

1日以上触っていないウィンドウには z が付き、Alt+f の一覧の下に移ります。返事を待っているものが埋もれません。

Measures how long agents wait on you

待ち時間を測る

The status line shows how long agents sat waiting on you today and your median reply time, with a green ▼ when today's median beats your 7-day median. Alt+/ adds a daily graph and today's timeline.

今日エージェントを待たせた合計と、返事までの時間の中央値をステータスバーに出します。今日の中央値が直近7日より短ければ、緑の ▼ が付きます。日ごとのグラフとタイムラインは Alt+/ で見られます。

Windows named by task

ウィンドウ名は自動で付く

Each window takes the first line of your prompt, or a model you pick sums up your last few prompts. Short replies like "ok" never rename it, and a name you set yourself stays.

依頼の1行目か、指定した LLM のまとめから名前を付けます。「OK」「進めて」のような返事では変わらず、自分で付けた名前も上書きしません。

Claude Code, Codex, Gemini

Claude Code・Codex・Gemini

Run any mix. They share one list and one Alt+a.

混ぜて使っても、同じ一覧に並びます。

Settings on Alt+,

設定は Alt+, から

Pick what Alt+n starts, the language (English, 日本語, ไทย), status rows and more from a menu. Choices save to junban's own file, so your tmux.conf stays yours.

Alt+n で起動するもの、言語（英語・日本語・タイ語）、ステータスバーの行数などをメニューで変えられます。選んだ内容は junban 専用のファイルに保存し、tmux.conf は書き換えません。

Your VS Code windows stay put

VS Code では移動先のウィンドウが前面に出る

Alt+a brings the VS Code window showing that agent to the front (or opens its folder) instead of swapping the terminal you're in. This works when each VS Code window runs its own tmux session.

VS Code のウィンドウごとに別の tmux セッションを使っている場合、Alt+a を押すと、移動先のエージェントを表示している VS Code のウィンドウが前面に出ます（なければそのプロジェクトのフォルダを開きます）。今使っているターミナルの表示は切り替えません。

Alt+n never looks frozen

Alt+n で起動した直後も止まって見えない

An agent can take seconds to draw anything. The new window shows a spinner right away, and its tab shows ◌ until the agent is up.

エージェントは画面が出るまで数秒かかることがあります。新しいウィンドウではすぐにスピナーが回り、起動が終わるまでタブに ◌ が付きます。

Keeps itself up to date

自動でアップデート

Once a day it updates to the newest release that passed CI, and says so on the status line. It never touches a checkout with local changes or a pinned version. Alt+, → Update now does it immediately.

1日に1回、テストを通った最新のリリースに更新し、更新したらステータスバーで1回だけ知らせます。手元に変更があるときや版を固定しているときは更新しません。Alt+, の「今すぐアップデート」でも更新できます。

No daemon

常駐プログラムなし

Runs on tmux and bash (Python 3 for some features). Nothing stays running: work rides on tmux's own status refresh.

tmux と bash で動きます（一部の機能は python3 を使います）。処理は tmux のステータスバーの更新に合わせて実行します。

Questionsよくある質問

Common questions

導入前によく聞かれること

How is it different from other tmux status plugins for agents?エージェントの状態を出すほかの tmux プラグインと何が違う？

Two things we didn't find elsewhere: the status line shows your next key, and idle windows move out of the way. It also puts tab badges, a jump to the longest wait and a wait meter in one tmux plugin with no daemon. Others each do some of these; see the comparison.

次に押すキーの表示と、放置したウィンドウを一覧の下に移す機能は、ほかのツールでは見つかりませんでした。また、タブの印、いちばん長く待っているものへの移動、待ち時間の計測を、常駐プログラムなしの tmux プラグイン1つで使えます。それぞれの一部はほかのツールにもあります（比較表）。

Does it send anything anywhere?どこかにデータを送る？

Nothing about you or your work by default. State lives in tmux options, and the wait meter in a local file only you can read. Once a day junban asks GitHub for a newer release (a git fetch; Alt+, → Updates → off stops it). Two things leave the machine only if you turn them on: with a model URL set, your recent prompts and the agent's reply go to that URL to name the window and write the one-line recap (a local Ollama keeps them on your machine); with a notify command set, the recap goes wherever that command sends it. A public ntfy.sh topic can be read by anyone who knows its name.

標準では、作業の内容は送りません。記録は自分のパソコンにだけ残ります。1日に1回、新しいリリースがないか GitHub に問い合わせます（git fetch。Alt+, の「アップデート」をオフにすると止まります）。自分で設定した場合だけ、次の2つを送ります。LLM を設定すると、ウィンドウ名と1行の要約を作るために、最近のやり取りを設定した送り先に送ります（ローカルの Ollama なら手元から出ません）。通知を設定すると、ステータスバーに出る1行の要約を通知先に送ります。ntfy.sh の公開トピックは、名前を知っていれば誰でも読めます。

Will it change how my tmux looks?tmux の見た目は変わる？

By default it brings its own status line. Add set -g @junban-theme off to ~/.tmux.conf, before the plugin line, to keep yours; junban then adds only its badges, the waiting count and the guide rows (set -g @junban-guide off drops those rows).

標準では junban のステータスバーに変わります。今の見た目のままにしたい場合は、~/.tmux.conf のプラグインを読み込む行より前に set -g @junban-theme off を書きます。その場合、junban が加えるのはタブの印、返事待ちの件数、ステータスバーの案内の行です（案内の行は set -g @junban-guide off で消せます）。

Why tmux, and not an app or a VS Code extension?なぜ tmux？　アプリや VS Code 拡張ではないの？

Because that's where many people already run their agents, including over SSH. There is no daemon and no app: if tmux is up, junban works.

多くの人が、すでに tmux の中でエージェントを動かしているからです。SSH 先でも同じように使えます。アプリも常駐プログラムもないので、tmux が動いていれば junban も動きます。

What about other agents?ほかのエージェントでも使える？

Claude Code, Codex CLI and Gemini CLI are built in. Anything that can run a command when it needs you or finishes can call scripts/state.sh waiting or done.

使えます。Claude Code・Codex CLI・Gemini CLI には標準で対応しています。それ以外も、返事待ちや完了のときにコマンドを実行できるツールなら、scripts/state.sh waiting（または done）でつながります。

Why the name?名前の由来は？

順番 (junban) is Japanese for "whose turn" or "in order".

「順番」から付けました。待たせている順に、次に返事をするエージェントを示します。
