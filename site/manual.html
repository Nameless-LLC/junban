    Everything junban does, and how to tune it.

    junban の全機能と、その調整方法。

    You only need Alt+a. The rest is here for when you want it. Everything below matches the current release.

    覚えるのは Alt+a だけで十分です。ほかの機能は、必要になったときにここで調べてください。内容は最新版に合わせています。

    Contents目次

      Get startedはじめに

      Run this in a terminal. It installs junban into tmux, reloads tmux, and connects Claude Code if you have it.

      ターミナルでこれを実行します。tmux に junban を入れて読み込み直し、Claude Code があればそちらにもつなぎます。

      curl -fsSL https://raw.githubusercontent.com/Nameless-LLC/junban/main/install.sh | bash

      With TPM (the tmux plugin manager), add set -g @plugin 'Nameless-LLC/junban' to ~/.tmux.conf, press prefix + I, then connect Claude Code:

      tmux のプラグイン管理ツール TPM を使う場合は、~/.tmux.conf に set -g @plugin 'Nameless-LLC/junban' を足して prefix + I を押し、Claude Code をつなぎます。

      claude plugin marketplace add Nameless-LLC/junban && claude plugin install junban@junban

      Needs tmux 3.2 or newer and bash. python3 and fzf are optional but recommended: python3 fixes stuck badges and writes recaps and reports; fzf makes the Alt+f list searchable. Works on Linux and macOS.

      必要なのは tmux 3.2 以上と bash です。python3 と fzf は任意ですが、入れておくのがおすすめです。python3 はバッジの自動修復・1行要約・集計に、fzf は Alt+f の一覧の検索に使います。Linux と macOS で動きます。

      New Claude Code sessions report their state from the first prompt. Press Alt+/ any time for the keys.

      新しく始めた Claude Code のセッションは、最初の依頼から状態を報告します。キーを忘れたら、いつでも Alt+/ を押してください。

      Badges状態バッジ

      Each tmux tab shows what its agent is doing.

      tmux の各タブに、そのエージェントの状態が出ます。

      BadgeバッジMeaning意味
      ✋Waiting on you: a question, or permission to run something. Clears when you answer.あなたの返事待ち（質問、または実行の許可）。返事をすると消えます。
      ✓Finished, and you haven't looked yet. Clears the moment you open the window, or come back to that terminal.作業が終わり、まだ見ていない。そのウィンドウを開いた瞬間か、その端末に戻った時点で消えます。
      ●Working.作業中。
      zUntouched for a day (@junban-stale-hours). Sinks to the bottom of the Alt+f list.1日以上触っていない（@junban-stale-hours）。Alt+f の一覧で下に移ります。

      The right end of the status bar counts all sessions: ✋ waiting, ✓ done, ● running. Next to it sits a small mascot whose face follows your agents:

      ステータスバーの右端には、全セッションの件数（✋ 返事待ち・✓ 完了・● 作業中）が出ます。その隣には、状況に合わせて表情が変わるマスコットがいます。

      [▮ ▮]!someone is waiting on you誰かがあなたを待っている
      [◠ ◠]one finished作業が終わった
      [▮▮ ]agents are workingエージェントが作業中
      [▬ ▬]znothing to do何もすることがない

      Badges fix themselves

      バッジは自動で直る

      Press Esc mid-turn and Claude Code sends no "stopped" event, so a tool that only listens to hooks would say "working" forever. Every few seconds junban checks Claude Code's own session records in ~/.claude/sessions, and walks the process tree to be sure which pane it is looking at, then corrects the badge.

      作業の途中で Esc を押すと、Claude Code は「止まった」というイベントを送りません。フックだけを見るツールでは「作業中」のまま固まります。junban は数秒ごとに Claude Code 自身のセッション記録 ~/.claude/sessions を確認し、プロセスの親子関係からどのウィンドウかを確かめたうえで、バッジを直します。

      Keysキー

      If your terminal doesn't send Alt, every key has a prefix fallback.

      Alt キーが使えない端末でも、prefix の後に押すキーで同じことができます。

      KeyキーprefixWhat it does動作
      Alt+aaGo to the agent that needs you most: ✋ before ✓, longest wait first.いちばん待たせているウィンドウへ移動。✋ が ✓ より先、待った時間の長い順。
      Alt+ffEvery agent in one list, neediest first, with a live preview.全エージェントの一覧。待たせている順で、中身のプレビュー付き。
      Alt+nCStart a new agent in this directory.このディレクトリで新しいエージェントを起動する。
      Alt+ggScratch shell in a popup. Close it; what you ran is still there next time.ポップアップのシェル。閉じても中身は残り、次に開くと続きから使えます。
      Alt+//All keys, today's timeline and the wait report.キーの一覧、今日のタイムライン、待ち時間のレポート。
      —TToday's timeline. No Alt key by default (Alt+t toggles thinking in Claude Code); set @junban-key-timeline to add one.今日のタイムライン。Alt キーは標準では割り当てていません（Claude Code では Alt+t が思考の切り替えのため）。@junban-key-timeline で追加できます。
      Alt+1…9—Window by number.番号のウィンドウへ移動。
      Alt+[ Alt+]—Previous / next window.前 / 次のウィンドウ。
      Alt+Tab—The window you were just in.直前のウィンドウに戻る。

      On macOS, let Option act as Alt: in iTerm2, Profiles → Keys → Left Option key: Esc+; in Terminal.app, Settings → Profiles → Keyboard → Use Option as Meta key.

      macOS では Option を Alt として使えるように設定します。iTerm2 は Profiles → Keys → Left Option key を Esc+ に、ターミナル.app は 設定 → プロファイル → キーボード →「Option キーをメタキーとして使用」をオンにします。

      The Alt+/ and timeline popups scroll with the arrows, PgUp/PgDn, Space or the mouse wheel; any other key, or a click inside, closes them.

      Alt+/ とタイムラインのポップアップは、矢印キー・PgUp/PgDn・Space・マウスホイールでスクロールし、ほかのキーを押すかポップアップの中をクリックすると閉じます。

      The Alt+f list

      Alt+f の一覧

      Agents that need you come first, each with its badge, its name and what you last asked it. Type to filter by name or by what you asked; the preview shows the window live. Enter goes there, Esc closes. Without fzf you get tmux's own chooser with the same order.

      あなたを待っているウィンドウから順に、バッジ・ウィンドウの名前・最後に頼んだ内容が並びます。文字を打つと名前や依頼内容で絞り込め、プレビューにはそのウィンドウの今の画面が出ます。Enter で移動、Esc で閉じます。fzf がない場合は、tmux 標準の選択画面が同じ順番で出ます。

      Alt+n and worktrees

      Alt+n と worktree

      Alt+n opens a window in the current directory and starts your agent (@junban-agent-cmd, default claude). If another agent already works in that git tree and the agent is Claude Code, the new one starts in its own worktree (claude --worktree), so the two never edit the same files. @junban-new-worktree off keeps the plain behaviour.

      Alt+n は今のディレクトリで新しいウィンドウを開き、エージェントを起動します（@junban-agent-cmd、標準は claude）。同じ git ツリーで別のエージェントがすでに動いていて、起動するのが Claude Code なら、新しい方は別の worktree（claude --worktree）で起動するので、2つのエージェントが同じファイルを編集することはありません。@junban-new-worktree off にすると、この切り替えをしません。

      Status lines 2 and 3ステータスバーの2・3行目

      junban adds two status lines under the window tabs. The second line says what needs you, or today's wait when nothing does; the third lists the keys. Nothing to memorise.

      junban はウィンドウのタブの下に2行を足します。2行目は対応が必要なもの、無ければ今日の待ち時間。3行目はキーです。何も覚えなくて済みます。

      Calm. Today's wait on the second line, the keys worth knowing on the third. While the prefix (Ctrl+b) is down, the third line lists what can follow it instead.

      平常時。2行目に今日の待ち時間、3行目に覚えておくと便利なキー。prefix（Ctrl+b）を押している間は、3行目が続けて押せるキーに変わります。

      kept waiting 42m today · median reply 3m10s
      Alt+a nextAlt+f all agentsAlt+1-9 that windowAlt+n new agentAlt+g scratch shellAlt+/ keys
      今日の待ち時間 42分 · 返答の中央値 3分10秒
      Alt+a 次へAlt+f 一覧Alt+1-9 その番号へAlt+n 新しいエージェントAlt+g シェルAlt+/ キー一覧

      Someone is waiting. A red banner with the key, and one line on what the next agent wants.

      誰かが待っているとき。赤い表示で押すキーを示し、次に移動するウィンドウが何を求めているかを1行で出します。

      ✋ 2 waiting on you → Alt+a to jumpdb migration: wants to run psql on dev
      ✋ 返事待ちが2件 → Alt+a で移動DB 移行: 開発 DB で psql を実行したい

      Someone finished. A green banner, with how the work turned out.

      誰かが終わったとき。緑の表示と、作業の結果の1行が出ます。

      ✓ 1 finished → Alt+a to reviewpricing page copy: 3 files changed, tests pass
      ✓ 1件の作業が完了 → Alt+a で確認料金ページの文言: 3ファイル変更、テスト成功

      The banner sits on the second line; today's wait moves to its right end when there is room. On a narrow terminal the recap is cut first, so the banner always fits.

      この赤・緑の表示は2行目に出ます。幅に余裕があれば、今日の待ち時間はその右端に移ります。端末の幅が狭いときは1行要約から省くので、押すキーの表示は必ず残ります。

      @junban-guide-lines 2 drops the keys row once you know the keys. While the prefix (Ctrl+b) is down, the remaining row lists what can follow it. @junban-tint washes the banner's colour over its row (@junban-tint-waiting for ✋).

      @junban-guide-lines 2 にすると、キーの行をなくします。prefix（Ctrl+b）を押している間は、残った行に続けて押せるキーが出ます。@junban-tint は赤・緑の色を行全体に薄く広げます（✋ のときは @junban-tint-waiting）。

      One-line recaps1行要約

      When an agent asks you something, wants permission or finishes, junban writes one line on it: the question, the command it wants to run, or how the work turned out ("tests pass, PR #12 opened"). It shows in the banner, in the Alt+f list and in phone notifications, so you can decide before you switch.

      エージェントが質問したとき、許可を求めたとき、作業を終えたときに、その内容を1行にまとめます。質問の中身、実行したいコマンド、作業の結果（「テスト成功、PR #12 を作成」など）です。ステータスバー、Alt+f の一覧、スマホ通知に出るので、ウィンドウを切り替える前に判断できます。

      With a namer model set (below) the model writes it; otherwise it is the first real line of the reply. @junban-recap off turns it off.

      命名用のモデルを設定していれば（次の項目）モデルが書き、なければ返答の最初の意味のある1行を使います。@junban-recap off で止められます。

      Window namesウィンドウの名前

      Windows are named after what you asked. Short replies ("ok", "yes", "進めて", "ครับ"), slash commands, shell escapes and pasted blocks never rename anything. A window you rename yourself (prefix ,) is left alone for good.

      ウィンドウには、あなたが頼んだ内容から名前が付きます。「OK」「はい」「進めて」のような短い返事、スラッシュコマンド、シェル実行、貼り付けた長文では変わりません。自分で名前を付けたウィンドウ（prefix ,）は、それ以降ずっとそのままです。

      # default: the first meaningful line you typed
set -g @junban-rename prompt
# or let a model summarise your last few prompts
set -g @junban-rename llm
set -g @junban-namer-url http://localhost:11434      # Ollama, or an OpenAI-compatible …/v1
set -g @junban-namer-model qwen3:8b
set -g @junban-namer-key OPENAI_API_KEY             # env var holding the key (…/v1 only)

      A small local model names a window in under a second. If the model is unreachable, the prompt is used.

      自分の PC で動かす小さなモデル（Ollama など）なら、1秒以内に名前が付きます。モデルにつながらないときは、頼んだ内容をそのまま使います。

      The wait report待ち時間のレポート

      A wait runs from the moment an agent asks you something (✋) or finishes (✓) until you answer or look. If it finishes while you are watching, that is no wait at all. One wait counts for at most @junban-meter-cap minutes (60), so a night away doesn't swamp the numbers.

      待ち時間は、エージェントが質問した（✋）か作業を終えた（✓）瞬間から、あなたが返事をするか見に行くまでです。見ている最中に終わった分は数えません。1回あたり最大 @junban-meter-cap 分（60分）で打ち切るので、一晩放置しても数字が崩れません。

      • The status line shows today's total and your median reply, against the seven days before.
      • ステータスバーに、今日の合計と返答の中央値が、直近7日との比較付きで出ます。
      • Alt+/ adds a bar per day, this week against last, your best day, today's slowest windows, and a streak of days with a median reply within @junban-goal minutes (5). The mascot comments on your week.
      • Alt+/ では、日ごとの棒グラフ、今週と先週の比較、自己ベストの日、今日いちばん待たせたウィンドウ、返答の中央値が @junban-goal 分（5分）以内だった日の連続記録が見られます。マスコットが1週間の様子にひとこと添えます。
      • scripts/stats.sh 30 goes back 30 days.
      • scripts/stats.sh 30 で30日前までさかのぼれます。
        How long your agents waited on you — last 7 days

  day          waited   count   median   ✋    ✓
  10/16      10h12m      139      55s     0  139   ████████████████
  10/18 today  2h53m      22    4m23s     0   22   ████▌
  Best day: 10/16, median reply 55s
  2 days in a row with a median reply within 5m
        エージェントがあなたを待った時間 — 直近7日

  日付         待ち時間   回数    中央値   ✋     ✓
  10/16        10時間12分    139      55秒    0   139   ████████████████
  10/18 今日    2時間53分     22   4分23秒    0    22   ████▌
  自己ベスト: 10/16 返答の中央値 55秒
  2日連続で返答の中央値が5分以内

      The timelineタイムライン

      prefix T (and the top of Alt+/) shows when your agents worked today: one row per window, █ working, ▓ waiting for your answer, ▒ done and not looked at. Below it: when you were active, how long agents worked, how long they waited on you, and how many ran at once. scripts/timeline.sh 1 shows yesterday.

      prefix T（と Alt+/ の上部）で、今日エージェントがいつ動いたかが見られます。ウィンドウごとに1行で、█ 作業中、▓ あなたの返事待ち、▒ 完了・未確認です。下には、稼働していた時間帯、エージェントの作業時間、あなたを待った時間、最大いくつのウィンドウが同時に動いたかが出ます。scripts/timeline.sh 1 で前日を表示します。

      It is a view for you, about your own day. It stays on your machine.

      自分の1日をふり返るための、自分用の画面です。データは自分の PC から出ません。

      Notifications通知

      When an agent starts waiting or finishes, junban can run a command with the message (including the recap) on stdin.

      エージェントが返事待ちになったときや作業を終えたときに、コマンドを実行できます。メッセージ（1行要約を含む）は標準入力で渡されます。

      # desktop (Linux)
set -g @junban-notify-cmd 'xargs -0 notify-send junban'
# phone, via ntfy
set -g @junban-notify-cmd 'curl -s -d @- ntfy.sh/your-topic'

      A public ntfy.sh topic can be read by anyone who knows its name. Pick a long random one, or run your own server.

      ntfy.sh の公開トピックは、名前を知っていれば誰でも読めます。長くてランダムな名前にするか、自前のサーバーを使ってください。

      AgentエージェントSetup設定You getできること

      Both keep your own hooks, replace only junban's entries (safe to run again) and leave a .bak. Add --print to see what would be written. Codex asks you to trust new hooks once: open /hooks in Codex. To make Alt+n start Codex, set -g @junban-agent-cmd codex.

      どちらも既存のフックは残し、junban の分だけを書き換え（何度実行しても安全）、.bak を残します。--print を付けると、書き込む内容を表示するだけで終わります。Codex は新しいフックを一度だけ承認する必要があるので、Codex で /hooks を開いてください。Alt+n で Codex を起動したい場合は set -g @junban-agent-cmd codex にします。

      Anything else that can run a command when it needs you or finishes can drive junban:

      入力待ちや完了のときにコマンドを実行できるツールなら、何でもつなげます。

      ~/.tmux/plugins/junban/scripts/state.sh running   # or waiting | done | idle | clear

      VS Code terminalsVS Code のターミナル

      If you keep one VS Code window per project, each terminal attached to its own tmux session, Alt+a raises the VS Code window that already shows the target, instead of swapping this terminal to another project. Plain terminals and web terminals switch in place. @junban-vscode-raise off always switches in place.

      プロジェクトごとに VS Code のウィンドウを分け、それぞれのターミナルを別の tmux セッションにつないでいる場合、Alt+a は行き先をすでに表示している VS Code のウィンドウを前面に出します。今のターミナルの中身を別プロジェクトに入れ替えることはしません。普通の端末や Web のターミナルでは、その場で切り替えます。@junban-vscode-raise off にすると、常にその場で切り替えます。

      All options設定一覧

      All optional. Put them in ~/.tmux.conf before the plugin line, then reload tmux.

      すべて任意です。~/.tmux.conf の、プラグインを読み込む行より前に書き、tmux を読み込み直します。

      # Look
set -g @junban-theme on            # off = keep your theme, only add badges and the counter
set -g @junban-position top        # top | bottom
set -g @junban-guide on            # status lines 2 and 3
set -g @junban-guide-lines 3       # 2 = no keys row; the keys show after the prefix
set -g @junban-tint 20             # % of the banner colour washed over its row (0 = off)
set -g @junban-tint-waiting 35     # the same for ✋
set -g @junban-mascot on           # off = hide the face
set -g @junban-name-width 12       # characters of a window name on a tab
set -g @junban-lang ja             # en | ja | th (default: from $LANG)

# Keys ("" to unbind)
set -g @junban-key-jump M-a
set -g @junban-key-list M-f
set -g @junban-key-new M-n
set -g @junban-key-scratch M-g
set -g @junban-key-help M-/
set -g @junban-key-timeline ""     # e.g. M-y
set -g @junban-nav-keys on         # Alt+1..9, Alt+[ ], Alt+Tab, Alt+z
set -g @junban-prefix-keys on      # prefix a f C g / T

# Agents
set -g @junban-agent-cmd claude    # what Alt+n starts
set -g @junban-new-worktree auto   # off = never start in a separate worktree
set -g @junban-vscode-raise on     # off = Alt+a always switches this terminal
set -g @junban-recap on            # one line on what each agent needs

# Habits and numbers
set -g @junban-scan-interval 30    # seconds between those git checks
set -g @junban-stale-hours 24      # z after this long untouched (0 = off)
set -g @junban-meter on            # wait total on the status line
set -g @junban-meter-cap 60        # minutes one wait can count for
set -g @junban-goal 5              # streak: days with a median reply within this

# Window names: see "Window names"
set -g @junban-rename prompt       # off | prompt | llm

# Notifications: see "Notifications"
set -g @junban-notify-cmd '…'

      Colours: @junban-color-waiting, -done, -running, -bg, -bg2, -fg, -accent, -muted, -dim, -key, -current-bg. With your own theme, put #{E:@junban-badge} anywhere in a format.

      色: @junban-color-waiting・-done・-running・-bg・-bg2・-fg・-accent・-muted・-dim・-key・-current-bg。自分のテーマを使う場合は、#{E:@junban-badge} を好きなフォーマットに入れるとバッジが出ます。

      Your dataデータの扱い

      State lives in tmux window options. Two logs are kept in ~/.local/state/junban/ (or $XDG_STATE_HOME/junban), readable only by you (files 0600, folder 0700):

      状態は tmux のウィンドウのオプションに持っています。記録は ~/.local/state/junban/（または $XDG_STATE_HOME/junban）の2つのファイルだけで、自分しか読めない権限（ファイル 0600、フォルダ 0700）です。

      • waits.tsv: start, end, kind and window name of each wait. Feeds the meter and the report.
      • waits.tsv: 待ちごとの開始・終了・種類・ウィンドウの名前。メーターとレポートに使います。
      • states.tsv: each change of state with its window name. Feeds the timeline. No prompts.
      • states.tsv: 状態の変化とウィンドウの名前。タイムラインに使います。依頼の内容は入りません。

      Nothing leaves your machine unless you set a namer URL or a notify command, and then it goes only where you pointed it.

      命名用の URL か通知コマンドを設定しない限り、何も外に出ません。設定した場合も、送り先は自分で指定した場所だけです。

      Troubleshootingうまく動かないとき

      ~/.tmux/plugins/junban/scripts/doctor.sh

      Or /junban:doctor in Claude Code. It checks tmux, the plugin and each agent's hooks, prints ok / warn / FAIL with what to do, and leaves out window names, prompts and secrets so you can paste it into a bug report.

      Uninstallアンインストール

      1. Remove the junban line from ~/.tmux.conf (run-shell …/junban.tmux, or the @plugin line).
      2. ~/.tmux.conf から junban の行（run-shell …/junban.tmux、または @plugin の行）を消します。
      3. Delete ~/.tmux/plugins/junban and, if you like, ~/.local/state/junban.
      4. ~/.tmux/plugins/junban を削除します。必要なら ~/.local/state/junban も消します。
      5. In a terminal: claude plugin uninstall junban@junban. For Codex or Gemini, restore the .bak that setup left.
      6. ターミナルで claude plugin uninstall junban@junban を実行します。Codex・Gemini は、設定時に残した .bak を戻します。
      7. Restart tmux (tmux kill-server) to clear the keys and status lines.
      8. tmux を再起動（tmux kill-server）すると、キーとステータスバーが元に戻ります。
